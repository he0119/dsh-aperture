# AGENTS.md — Agent Notes

这里是**决策记录**：代码与文档承载不了的*为什么*，以及*放弃了什么*。每条信息只写
一处——笔记写决策依据与备选方案，`docs/` 写当前机制，根 `AGENTS.md` 写每轮都要在
上下文里的硬约束。

## 布局与命名

`{lifecycle}/{class}/yyyy-mm-dd-topic-title.md`，两个维度都编码在路径里。

- **生命周期**是笔记的状态，随状态在目录之间移动：
  - `proposed/`：实施前评审的提案，尚未构建（或仅部分构建）。
  - `implemented/`：决策已交付。文件描述**已交付的现实**，并与代码保持同步。
  - `rejected/`：讨论后被否决的提案。仅当它的依据仍能挡住一个诱人且影响重大的错误
    时保留，否则删掉。
- **类别**是决策的种类（封闭集合，别新建目录）：
  - `feature`：面向用户或模型的新能力。
  - `bug-fix`：修正缺陷。
  - `simplification`：在**不增加能力**的前提下移除代码、行为或对外范围。
  - `architecture`：关于**交付源码**的结构性决策：包之间的关系、运行时词汇。
  - `process`：代码**周边**的工具、策略或工作流——门禁、包管理器、依赖。
  - `testing`：测试基础设施与策略。
  - `architecture` 与 `process` 的界线：前者关乎我们交付的源码，后者关乎围绕源码的
    工具与流程。（不设 `refactor`：它与 `simplification` 重叠。）
- 文件名里的日期是该主题**首次提出**的时间，以 git 历史为准
  （`git log -S'<一句特征串>' --date=short --format='%ad %s'`，取最早的一条）。
- 笔记之间用相对 Markdown 链接互相引用，链接必须能解析。
- **本仓库还没有 `archived/`**：上游那套冻结层 + sha256 manifest 是 641 篇笔记时的
  产物。等「已交付但不太可能再指导未来工作」成为常态时再加，判据另写一篇笔记。

## 文件格式

每篇笔记的前三行严格为：

```markdown
# Agent Note: <标题>

Status: <状态>
```

后跟一个空行。`Status:` 必须与所在生命周期目录一致：

- `Status: proposed`
- `Status: implemented`
- `Status: rejected — <一句话原因>`

`Status:` 行不带日期、不带括号补充说明：文件名记首次提出日期，git 记其余一切。

正文以 `## Problem` 开头——动机要写成不依赖解决方案也能独立成立的一段。之后按生命
周期分叉，固定章节用下列名称且仅限这些名称，真正独特的技术章节（协议约定、schema
等）在必需章节之间自由组织：

- `implemented/`：`## Decision`（现在时，描述已交付的现实）→ 自定义 → `## Alternatives
  considered` → `## Consequences`。**禁止**出现 `## Proposal` / `## Plan` /
  `## Migration plan` / `## Acceptance criteria`——它们是提案用语，会随代码腐烂。
- `proposed/`：`## Proposal` → 自定义 → `## Alternatives considered` →
  `## Acceptance criteria` → `## Risks`。
- `rejected/`：保留提案时的章节，结论写在 `Status:` 行上。

`## Alternatives considered` **必须有**：每个真实的替代方案配一句它为什么落选。
记录决策时不记录它击败了什么，就是在邀请反复争论。

笔记是**中文单语**，没有语言切换栏——README 那一对的双语契约不覆盖笔记。

## 何时写一篇

只有代码、测试与现有文档都没能解释的决策理由具有长期价值时才写，并与改动同一个
提交。

- **豁免**：机械改动与局部 UI 调整——排版、间距、文案、配色微调不写笔记。
- **不豁免**：实质行为决策、局部 bug 修复、性能变更，规模小不是理由。
- 已有一篇笔记持有该决策就**更新它**，不要新建重复记录。
- 笔记**永远不被编辑成另一个决策**：用新笔记取代旧记录，并让两篇互相链接。
- `implemented/` 的笔记跟着代码走：路径、符号、默认值、机制变了就在同一次改动里就地
  改事实——但只改事实的表述，不改决策本身。

## 门禁

`test/notes.test.ts`（在 `pnpm test` 里跑）核：路径形状、三行头部、`Status:` 与目录
一致、`## Problem` 是第一个二级标题、必备章节在、禁止章节不在、相对链接可解析。
改笔记格式时同一次改动里改它。
