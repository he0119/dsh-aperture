# Agent Note: 模型编辑器挂在官方「模型」页的扩展位上

Status: implemented

## Problem

逐模型覆盖（显示名、别名、协议、容量、模态、推理）原来长在本插件的配置页上，而模型列在官方
「模型」页里：本插件注册的每一条路由都是那一页上的一行，用户看到模型的地方与改模型的地方隔着
一次跳转。「模型」页自己的编辑器对本插件用不上——它按设置命名空间挑布局
（`layoutOf`：`llm-deepseek` → DeepSeek 目录编辑器，`llm-pi-ai` → 端点和协议，其余一律
「其余字段在 cordis.patch.yml 中」加一颗禁用的「保存」），本插件的段是 `aperture`，于是那一行
只显示那句说明。

那一页倒是留了扩展位（它自己的 README 叫 Extension slots，`settings.models.provider-card` 与
`settings.models.footer`，0.1.7-rc.1 与 0.2.0-rc.2 两版的声明逐字相同）。真正要决定的是：两块
编辑器各挂哪儿、各管哪些模型。

两处约束互相拉扯。卡片座位是**键控**的，键是设置命名空间，因此本插件注册的每一行都会得到一块
——三条路由就是三块，画同一份清单等于把同一份东西抄三遍。页脚座位只有一块，但它在列表末尾，
离模型最远；而且没有路由可服务的模型（配置里手写的、清单里没有的那些）根本没有卡，`sync` 关掉
时连卡也不存在。

## Decision

模型清单用**同一个组件**（`src/client/ApertureModels.tsx`）注册到两个座位上，设置页
（`src/client/AperturePanel.tsx`）只剩实例地址与注册开关：

- `settings.models.provider-card`：本插件注册的每一条路由那一行里一块。注册键是设置命名空间
  `aperture`；组件从页主递进来的目录行（owner props 里的 `provider`）认出自己管哪一条路由，只画
  `model.route` 等于那个路由 id 的模型。
- `settings.models.footer`：列表末尾一块。它画报告里 `route` 为空的那几个；**一条路由都没注册时
  改成画全部**（`report.routes` 为空，卡片一块也不会渲染）；两者都为空、这一轮也没有可报告的问题时
  整块返回 `null`，不在别人的页上留空区域。

这一块**默认收着**（官方 `DisclosureRow` 折叠头，标题与模型数目留在头上）：卡片座位的派发不带
「这一行展开了吗」这个事实，页主对每一行都渲染这个座位，而一张卡里摊开十几行清单会盖过那一页本身
的内容；页主自己的编辑器（点「编辑」才出现的那一块）与这一块互不影响。翻过一次之后折叠头自己记着
状态，不再随报告刷新收回去。

两个座位都由「模型」页声明，本插件只注册内容；页主不给内部状态，因此「这一条路由是谁」只能从
owner props 读，而「该画哪些模型」只能从报告算。为此模型页那个包作为**类型依赖**进
`devDependencies` / `peerDependencies`（`^0.1.7-rc.1 || ^0.2.0-rc.1`）与 `dsh.client.inject`：
`import type {} from '@deepseek-ai/dsh-client-ui-settings-models/client'` 只取槽位声明，运行时不
require 它。

## Alternatives considered

**只挂页脚座位（一块完整清单）。** 最先试的就是这一版：改动最小、与原来的页面几乎一样。落选是因为
它把编辑面挪到了模型列表之外——模型列在上面，能改它们的那块在下面，用户看不出两者是一件事。

**只挂卡片座位。** 没有路由可服务的模型与 `sync` 关掉时都没有卡，等于把这些模型的编辑面整个拿掉
（协议那一项是它们唯一的出路）。页脚座位因此留着当兜底。

**卡片座位永远摊开。** 页主的座位在每一张卡上都渲染（不分是否点开「编辑」），永远摊开就是每张卡
里都插一段完整清单，三条路由三份。默认收着 + 折叠头是同一件事的最小代价。

**自己判断那一行有没有被展开。** owner props 里没有这个事实，只能去猜页主的 DOM（它的编辑器
出现与否），那是绑死在别人的私有结构上。页主以后若把「展开了吗」放进 owner props，这一块的
默认状态可以改由它决定。

**卡片座位画全部模型。** 三条路由就是三份一模一样的清单，而且「我在这张卡里改的到底是哪条路由
的模型」没有答案。

**换个设置命名空间冒充 `llm-pi-ai` / `llm-deepseek` 家族。** 那正是
[不写任何配置](../simplification/2026-10-03-no-configuration-writes.md)拿掉的东西：编辑器会写进
别人的配置段。而且那两个布局给的是端点、协议与模型目录，不是逐模型覆盖，换过去也得自己再挂一块。

**等上游给一个通用编辑器接缝。** 不必等：那两个座位从 0.1.7 起就在，正是为「本仓库之外的插件往这
一页加界面」准备的。

**把逐模型覆盖从界面拿掉，只留配置。** 这一层是现成可用的能力（容量、模态、别名、协议），拿掉它
是另一件事，不是这次挪位置的代价。

## Consequences

- 本插件注册几行路由，「模型」页上就有几块清单（各管自己那条路由），加上页脚最多一块。没有路由可
  服务的模型仍然可编辑，位置固定在列表末尾；两块都默认收着，用户点一下折叠头才看到清单。
- 「模型」页里那一行自己的编辑器对本插件**仍然是只读的**：那句「其余字段在 cordis.patch.yml 中」
  与禁用的「保存」就在本插件那块的上方，页主的内容本插件改不了。
- 设置的两项（实例地址、注册开关）留在插件页的包级配置槽位上，见
  [配置页挂在包级槽位](./2026-09-24-package-scoped-config-slot.md)；两个组件共用
  `src/client/shared.ts` 里的注入面类型、设置快照类型与「这一轮哪里不对」那两句话的算法。
- 那一页的槽位声明后到也没关系：三个座位都走 `ctx.slots.inject`，与
  [自带 provider 适配器](./2026-10-03-own-provider-adapter.md)之后剩下的接缝一致。
- 模型页那个包进了 peer 范围，`test/manifest.test.ts` 里「更早的宿主被预检挡下」那份名单因此有
  八个 DSH peer 而不是七个。
