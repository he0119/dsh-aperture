# Agent Note: 写入只碰自己拥有的键

Status: implemented

## Problem

插件的输出是**另一份配置**（`llm-pi-ai.providers`），那里同时躺着用户手写的
provider。每轮刷新都要写一次，因此有三个必须挡住的事：把别人的键覆盖掉、内容没变
也重写文件（触发文件监听回环）、网关临时不可达时把已经生效的目录清空。

## Decision

只碰 `llm-pi-ai.providers` 下本插件拥有的三个键（`route` / `route-responses` /
`route-anthropic`，默认即 `aperture` / `aperture-responses` /
`aperture-anthropic`），并且：

- **内容相同就不写**——每次刷新都对比解析后的段，避免无意义的重写和监听回环；
- **用路径操作写**——其它 provider 一个字段都不会动；
- **探测失败就不写**——网关临时不可达时保留已经生效的目录，而不是清空；
- **带 revision 写**——与其它写入者（比如模型页）冲突时重读一次再写；
- **路由没模型了就删掉**——避免留下指向旧目录的空路由；
- **关掉同步就撤下**——`sync: false` 表示「本插件不该在这里留东西」，那一轮刷新发
  的是一份空方案，`planSync` 把三个拥有键 unset 掉，配置段里别的 provider 不动；
- **写入必须从 HMR 事务之外发起**——见
  [刷新必须从 HMR 事务之外起跑](../bug-fix/2026-09-24-refresh-starts-outside-the-hmr-transaction.md)。

`src/sync.ts` 的 `planSync` 是这套规则的唯一实现：它输出一串逐键的 op，写入侧照做，
没有第二条清理路径。

## Alternatives considered

**整份 `providers` 段重写。** 用户手写的 provider 会被抹掉，而写下去的内容跟
「用户写了什么」混成同一份账，事后分不出哪些是插件放进去的。

**只加不减，路由空了就留着。** 空路由会一直指向一个已经不存在的目录，界面上看不出
还有谁在服务，用户只能自己去翻 `llm-pi-ai` 段。

**`sync: false` 时什么也不做。** 那么已经发布出去的路由会一直留着——用户关掉同步
的意图正是「把这里的东西撤下来」，而不做等于把这个开关变成只挡新增。

**每轮刷新都重写一遍以保证「最终一致」。** 写入会不断触发文件监听，刷新被自己的
写入唤醒，形成回环。

## Consequences

- **改了 `route` 的路由名之后，旧键会留在 `llm-pi-ai.providers` 里**：插件只认自己
  当前拥有的三个键，无法知道历史上用过哪些名字。它不会报错，只是不再刷新；要清理
  得手动删掉那一行。
- 撤下与「发布 N 条路由」走的是同一条路（空方案），因此「关掉同步」这条路径不需要
  单独测一遍写入被拒的分支。
