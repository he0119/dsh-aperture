# Agent Note: 逐模型编辑是稀疏的字段补丁

Status: implemented

## Problem

界面上一行模型对应设置文档里 `aperture.models` 的一个条目，而那一行只编辑其中几个
字段：容量与模态可以改，`modelAliases` 走另一条键，`reasoningEfforts` 界面根本
不编辑。每一次写入都发生在多行共存的页面上，因此必须回答：这一次保存到底写了什么。

## Decision

端点就是 `(id, patch)`：一次一个模型、一次版本校验，补丁**稀疏**——界面只发它改动
过的字段，没提到的原样留在设置文档里。具体口径：

- 空串与 `null` 表示「这一项不覆盖」；`patch` 传 `null`（而不是缺省）才是「整条
  撤销」，缺省是调用方写错了，宿主会拒绝——「什么都没改」与「撤掉一切」差得太远。
- 容量、模态、推理与协议落在 `models` 的对应条目上，清单别名落在 `modelAliases[id]`。
- 写入时按**位置**替换数组元素，改一个字段不会让这条覆盖挪到数组末尾。
- 撤销别名之前先看**用户层**有没有这个键：界面显示的是生效别名，它可能来自组合层或
  清单，删一个不存在的键要么白写、要么被设置服务当成坏路径拒绝。
- 非法值在写入前就被挡下来：写进设置文档的坏值会让下一轮刷新的 `resolveConfig` 直接
  抛异常，那时用户已经在别处改坏了配置。
- 「清空覆盖」也是这一行的补丁（见
  [清空覆盖写的是这一行的补丁](../bug-fix/2026-09-24-clear-override-writes-the-line-patch.md)）。

## Alternatives considered

**整条覆盖式写入（每行发一份完整对象）。** 会抹掉界面不编辑的键——`reasoningEfforts`
就是这么被顺手清掉的。

**批量提交（一次改好几个再一起提交）。** 界面上不存在「一次改好几个再一起提交」
这种动作，却会多出「一半写下去怎么办」这种必须解释的失败态。

**按值而不是按键判断改动。** 「已覆盖」的判据是**键在不在用户层里**（与官方同一条
判据），不是值等不等于组合层；按值判断会让一行凭空多一颗「已覆盖」。

## Consequences

- 一次保存只影响一行，版本校验也只管这一次写入：写坏了只坏这一行。
- 界面不编辑的键仍然在覆盖名单里，因此「恢复默认」知道自己该整条撤。
