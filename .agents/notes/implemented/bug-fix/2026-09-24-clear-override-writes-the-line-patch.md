# Agent Note: 清空覆盖写的是这一行的补丁

Status: implemented

## Problem

报告里的 `overrideKeys` 写着这一行**确实**在用户层里写过哪几项。「清空覆盖」如果
丢掉 `aperture.models` 里整条条目，会把界面根本不编辑的键（例如 `reasoningEfforts`）
一起扔掉。反过来，只要有**一个**界面不认识的键在名单里，就只能整条撤：只清认得的
那几项，这一行在报告里仍然是「已覆盖」，那颗标签会按不下去。

## Decision

按钮把认得的几项逐个 `null` 发出去（别名那一项用空串——它单独落在 `modelAliases`
里），只要名单里有一个界面不认识的键就整条撤。

## Alternatives considered

**一律整条删除。** 会扔掉界面不编辑的键，而用户看不出那些键是他自己写的还是这里
删掉的。

**一律只清认得的键。** 剩下的键让这一行在报告里永远是「已覆盖」，那颗标签按不下去
——这正是要修掉的现象。

## Consequences

- 「清空覆盖」与「恢复默认」是同一条路径（发一串 `null` 的行补丁），区别只在认不
  认得名单里的键。
- 报告必须把用户层原样的键交出来，而不是解析后的配置（见
  [空值不算声明](2026-09-24-empty-values-are-not-declarations.md)）。
