# Agent Note: 空值不算声明

Status: implemented

## Problem

运行时 schema 给 `models[].input` 的缺省值是**空数组**，`reasoningEfforts` 也可能
被写成 `{}`；两者都不是「这个模型没有任何模态 / 没有任何推理档位」的意思（想声明纯
文本的是 `images: ignore`），却都会一路传到发布出去的 provider 里：

- `input: []` 抹掉发现到的模态，还谎称来源是配置；
- `{}` 更狠：schema 要求每个档位都有一个线缆写法，空对象于是被当成「声明了推理、却没有任何一
  档可用」，整条路由都注册不出去、每张路由卡都亮红点，而原因只写在「最近一次刷新」那一行里；
- 报告若按**解析后的配置**算「用户写过哪些覆盖」，`input: []` 就会让一行什么都没
  写过的模型挂上「已覆盖」，而按「恢复默认」发下去的是 `input: null`——用户层里
  根本没有这个键，写下去是空操作，那颗标签于是永远撤不掉。

## Decision

三处一起按「没写」处理：

- `registry.ts` 的 `declaredInput` 与 `profile.ts` 的 `declared` 把空数组、空对象
  当成未声明；
- 报告只收用户层原样的条目（`buildReport` 的 `declared`）并收成 `overrideKeys`：
  **键在不在用户层里**，与官方同一条判据；
- 写回时同理（`panel.ts` 的 `prune`）：生效值里的空值不会被搬进用户层，否则一次
  「保存」就等于替用户写下他从未写过的覆盖。

## Alternatives considered

**把空数组、空对象当成显式声明。** 这正是缺陷本身：它会覆盖发现结果，还会让适配器
拒收整段配置。

**只在界面层过滤。** 判断属于插件而不是界面（同
[稀疏补丁](../architecture/2026-09-23-sparse-per-model-field-patches.md)那条分工）；而且报告是从
Host 端组装的，界面过滤不掉已经写进报告的口径。

**改报告，让它按值而不是按键算「已覆盖」。** 官方同一条判据是**键在不在用户层
里**；按值算会让一行凭空多出或凭空消失一颗「已覆盖」。

## Consequences

- 单元测试里手写的选项对象没有这个 schema 缺省值，正是这一点让 `input: []` 躲了
  很久；因此相关用例**先过一遍 schema** 再断言。
- 界面不编辑的键（`reasoningEfforts`）也在覆盖名单里，这一条与稀疏补丁共同决定
  「恢复默认」的行为。
