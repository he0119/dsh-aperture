# Agent Note: 没有路由可服务的模型不在「模型」页出现

Status: implemented

## Problem

官方「模型」页说的是 dsh 里此刻能选哪些模型：每一行是一个 provider，行底下是它真的能服务
的模型。没有路由可服务的模型——配置里手写的、清单里没有的那些，以及只提供 Gemini 原生端
点、三种线缆协议都接不住的那些——不属于任何一行。给它们在列表末尾单开一块，等于把本插件
自己的区分（发现到的模型 / 有路由的模型）搬到别人的页面上：那一块列出来的模型在选择器里
永远选不到，而「这一页上列着」与「选择器里能用」是两件事，用户从这一块看不出来；块的位置
又在列表最末，离它要解释的那些模型隔着整页。

## Decision

「模型」页上只留 `settings.models.provider-card` 一个座位：本插件注册的每一行路由那一行里
一块，只画 `model.route` 等于那一行 id 的模型。能列在那一页上的模型因此一定有路由。

`settings.models.footer` 不再注册。没有路由可服务的模型改由本插件的配置页
（`plugins.bundle.config`）一句话交代：`AperturePanel` 从同一份报告里数出 `route` 为空的
那些，报出个数与最多五个 id（多的写「等 N 个」），并说明去哪儿给它们写协议——**那些模型在
界面上不再有编辑器**，改的地方是配置里的 `models[].protocol`。一条路由都没注册时（`sync`
关着，或这一轮什么都没注册成）那句话换成「这一轮没有注册任何路由」；注册失败的原因仍由原
来那句「这一轮哪里不对」说，两句不重叠。

配置页原来只读报告里那两句「这一轮哪里不对」，这一改之后它还要数这一群人。报告本身不用变
（`PanelReport.models` 一直带着 `route` 为空的那些）。

## Alternatives considered

**留着页脚座位当兜底。** 改动最小，也是[模型编辑器挂在官方「模型」页的扩展位上](../architecture/2026-10-03-models-page-extension-seats.md)
当初选它的理由：没有卡片的模型在界面上就再也没有入口。落选是因为那一块的语义与那一页不符
——它列出的模型在选择器里永远选不到，位置又在列表最末。

**把那个编辑器搬到配置页。** 技术上能搬（写逐模型覆盖的 Remote 就在这一页上用），但那是给
这些模型再开一个编辑入口，与「别在别人的页上占座位」是两件事；先把话说到，等真的需要就地
改这些模型时再做。

**在「模型」页留一行纯文字（不带编辑器）。** 那一页上的块都挂在某一行 provider 之下，孤零
零一行文字没有归属，仍然要在别人的页面上解释本插件的概念。

**什么都不说。** 用户在配置里写了模型、选择器里却没有，页面上没有任何线索。报告里那份事实
已经在界面上说了两句话（清单读不到、路由没注册上），多这一句是同一类信息。

## Consequences

- 「模型」页上本插件只剩每种有模型的路由那一块。`ApertureModels` 不再是两个座位共用的组件：
  `scope`、「一条路由都没注册时画全部」那个分支、以及「没有卡片头可依所以逐行写路由与协议」
  一起没了；那一页上每一行都归属于某一条路由，行内不再重复「路由 / 协议」。
- 配置页多两句话：没有路由可服务的模型（个数 + 最多五个名字），以及一条路由都没注册。它们
  是那些模型在界面上唯一的线索。
- 那些模型在界面上**没有编辑器**了：要接进路由得在配置里给 `models` 那一项写 `protocol`。
  只提供 Gemini 原生 `generateContent` 的模型本来就接不进来（README 的问答仍写着这件事）。
- 「模型」页里那一行自己的编辑器对本插件仍然是只读的，那一半的取舍见原来的那篇笔记。
